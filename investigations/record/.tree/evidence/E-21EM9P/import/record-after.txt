## Q-9WV3D7 Where does the record live, off every code branch? — answered

On a crash after an event's line is in the record worktree's file and before its commit, h-ref meets the build Goal's line 3 (no command reads part of a write) and h-record-worktree does not, because a reader of that worktree sees an event that git clean or git checkout there can still lose, while under h-ref a reader sees the event only once update-ref has landed. If h-record-worktree read only commits, it would be h-ref plus a checkout that adds nothing.

Selected: H-WQ2Q24
Design: hyp writes each event, and the bytes of each file it names, as git objects, then moves refs/hyp/record to a new commit with update-ref; an event exists for every reader of the clone only once the ref has moved, and no worktree holds the record's files.
